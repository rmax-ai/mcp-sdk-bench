## Interoperability (SPEC.md §8 INTEROPERABILITY, M2.2)

Cross-implementation pairings, each a real client from one SDK against a real server from another SDK in a fresh subprocess world. **Every cell below is run-verified** by `tests/interoperability/test_pairings.py` (connect/initialize, 6-tool discovery, get_ticket + probe_schema round-trip, clean teardown) and `tests/interoperability/test_version_negotiation.py` (wire-level protocolVersion evidence via the log-mode stdio proxy in `tests/conformance/helpers.py`). Protocol versions are captured from the wire, not SDK self-reporting. Machine-readable output: `results/latest/interoperability.json` (regenerated by `uv run mcpbench interop`).

| Pairing | Status | Negotiated protocolVersion (client-announced → wire) | Wire-level note |
|---|---|---|---|
| FastMCP client → FastMCP server | ✅ pass | 2026-07-28 → 2026-07-28 | FastMCP 4.0.2 opens with the modern `server/discover` probe (no legacy `initialize` on the wire); both sides run 2026-07-28. |
| FastMCP client → official server | ✅ pass | 2026-07-28 → 2026-07-28 | Official mcp 2.1.1 server answers `server/discover` with `supportedVersions: ["2026-07-28"]`; the client stamps 2026-07-28 on subsequent requests. |
| Official client → FastMCP server | ✅ pass | 2025-11-25 → 2025-11-25 | Official mcp 2.1.1 client offers `LATEST_HANDSHAKE_VERSION` (2025-11-25) on `initialize`; the FastMCP 4.0.2 server accepts it. |
| ADK client → FastMCP server | ✅ pass | 2025-11-25 → 2025-11-25 | ADK 2.8.0 embeds the mcp 1.29.1 client; legacy handshake at 2025-11-25 against the mcp 2.x-era FastMCP server negotiates cleanly. |
| ADK client → official server | ✅ pass | 2025-11-25 → 2025-11-25 | Same mcp 1.29.1 handshake against the official mcp 2.1.1 low-level server; no negotiation failure. |

Non-pass cells: none. Two honest caveats, both run-verified rather than hidden:

- **ADK client pairings see tools only.** `McpToolset` has no first-class MCP resource/prompt surface (M1 finding), so `resources_seen`/`prompts_seen` are 0 for ADK client rows — absence of a client surface, not a server deficiency (both servers serve the deployment-policy resource and incident-triage prompt, proven by the FastMCP/official client rows).
- **ADK protocol versions are proxy-captured.** `McpToolset` exposes no initialize result, so the ADK rows' versions come solely from the wire log (harness limitation, recorded as `exposes_protocol_version=False` in `tests/conformance/helpers.py` DISCOVERY_CONTRACT).
